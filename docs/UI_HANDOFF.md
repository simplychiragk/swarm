# Swarm UI Handoff Specification

For the frontend engineer working in `app/`. Backend assistant only updates `app/src/types/contracts.ts` to mirror shared types. All runtime integrations, endpoints, and event shapes are documented below.

---

## 1. WebSocket Streaming & Reconnection (`/ws`)

The sidecar provides a single bidirectional WebSocket endpoint at `ws://127.0.0.1:8000/ws`.

### Connection Parameters
- `run_id` (optional, default `"run-default"`): The ID of the run to attach to.
- `after_seq` (optional, integer): Sequence number for delta catch-up.

### Catch-Up Behavior
1. **Fresh Connection (`after_seq` omitted)**:
   - The sidecar immediately sends the current run's **latest whiteboard cards** (`card_upsert` envelopes) so the whiteboard renders immediately.
   - The sidecar then sends any active **pending approval gates** (`approval_request` envelopes).
   - Finally, the sidecar streams all chronological events (`events` with `seq >= 1`) so chat and feed history populate.
2. **Reconnection / Delta Catch-up (`after_seq=<seq>`)**:
   - The sidecar streams only events where `seq > after_seq`.
   - Prevents duplicate message rendering on transient network disconnects.

## 2. Event Envelope & Provenance Tagging

Every event broadcasted over WebSocket follows the standard envelope format:

```json
{
  "event": "feed_message" | "card_upsert" | "approval_request" | "agent_status" | "feed_chunk" | "plan_diff",
  "payload": { ... },
  "seq": 14,
  "run_id": "run-default",
  "provenance": "real" | "simulated" | "replay"
}
```

> [!IMPORTANT]
> The UI must safely ignore unknown event types for forward compatibility.

### Provenance Display Rules
To ensure honesty and transparency during evaluations and live demos:
- `"real"`: Real LLM generation, real TinyFish search/browser execution, and real tool output. Display with normal styling (or subtle green dot).
- `"simulated"`: Output from mock runners, fallback chains, or simulated fixtures (`SWARM_MODE=mock`). Display an **amber "MOCK / SIMULATED" tag or badge** in the feed/card header.
- `"replay"`: Output generated by re-streaming a past historical run (`POST /runs/{id}/replay` or `SWARM_DEMO_MODE=golden`). Display a **blue "REPLAY" indicator** with playback status.

## 3. Client Inbound Messages (UI -> Sidecar)

Frontend can send messages over the WebSocket at any time:

### A. User Prompt / Interview / Steering (`user_message`)
```json
{
  "event": "user_message",
  "payload": {
    "id": "usr-123456",
    "text": "Wait, add a phone number field too, with country code",
    "timestamp": "2026-10-24T22:30:00Z",
    "mode": "steer"
  }
}
```

**`mode` Options:**
- `"steer"` (default): Direct injection into active swarm. Queen computes plan diff, informs workers, modifies workspace.
- `"queue"`: Queen appends to queue and holds for the next phase.
- `"interrupt"`: Pauses workers immediately, awaiting user clarification.

### B. Human Approval Gate Response (`approval_response`)
```json
{
  "event": "approval_response",
  "payload": {
    "approval_id": "appr-abc-123",
    "card_id": "card-deploy",
    "decision": "approve" | "redirect",
    "note": "Optional feedback when redirecting",
    "scope": "once" | "run" | "deny"
  }
}
```

## 4. Structured Plan Diffs (`plan_diff`)

When steering modifies tasks, the sidecar emits a `plan_diff` event:

```json
{
  "event": "plan_diff",
  "payload": {
    "run_id": "run-default",
    "reason": "User steering: Wait, add a phone number field too, with country code",
    "timestamp": "2026-10-24T18:00:00Z",
    "changes": [
      {
        "task_id": "task-fe-phone",
        "title": "Add Phone Number & Country Code Selector",
        "action": "added",
        "lane": "FE",
        "reason": "Capture verified international phone number with country code picker"
      },
      {
        "task_id": "task-be-phone",
        "title": "Extend Waitlist Schema for Phone Validation",
        "action": "added",
        "lane": "BE",
        "reason": "Accept and validate optional phone & country_code in POST /api/waitlist"
      }
    ]
  }
}
```

**UI Rendering:**
- Any card whose title starts with `[EDITED]` should display an amber **"EDITED"** badge.

## 5. Live Whiteboard Evidence & Summary Cards

### Run Provenance & Verification Audit Card (`card-provenance-summary`)
Emitted on the whiteboard under the `Ops` lane before the release approval gate:
- Lists every tool call, its execution duration in milliseconds, and `[REAL]` vs `[SIMULATED]` provenance.
- Displays Decision Engine routing stats (`delivered`, `dropped`, `summarized`, and average confidence).

### Live Preview Serving
- The built application in `workspace/<run_id>/` is directly accessible at:
  `http://127.0.0.1:8000/runs/{run_id}/preview/`
- Backend API route: `POST http://127.0.0.1:8000/runs/{run_id}/preview/api/waitlist`

## 6. REST API Endpoints

| Endpoint | Method | Description |
|---|---|---|
| `GET /health` | GET | Sidecar heartbeat and mode status. |
| `GET /health/deps` | GET | Connectivity check for LLMs & TinyFish without exposing API keys. |
| `GET /runs` | GET | List historical and active runs (`?limit=50`). |
| `GET /runs/{id}` | GET | Get metadata and status for a specific run. |
| `GET /runs/{id}/events` | GET | Get ordered event log (`?after_seq=0`). |
| `GET /runs/{id}/cards` | GET | Get latest state projection for all cards in a run. |
| `GET /runs/{id}/approvals` | GET | Get approvals for a run (`?pending_only=true`). |
| `GET /runs/{id}/steers` | GET | Get steering receipts and plan diffs for a run. |
| `GET /runs/{id}/decisions/delivery` | GET | Get decision layer delivery decisions and routing statistics. |
| `POST /runs/{id}/replay` | POST | Stream past run over WebSocket (`{"speed": 1.0, "delay_seconds": 0.05}`). |
| `GET /runs/{id}/preview/` | GET | Serve the built landing page from the run workspace. |
| `POST /runs/{id}/api/waitlist` | POST | Waitlist submission backend endpoint. |
| `GET /runs/{id}/permissions` | GET | SQLite audit log of all security checks and decisions. |
| `GET /runs/{id}/artifacts/{path}` | GET | Stream files safely from the run's workspace (png, jpg, html, json, txt). |
| `GET /workspace/tree` | GET | Retrieve all project files and content for code viewer. |
| `PUT /workspace/files/{path}` | PUT | Edit a file in the workspace via permission executor. |
| `POST /workspace/files` | POST | Create a new file or directory in the workspace. |
